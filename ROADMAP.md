# AI Research Engineer Academy — Roadmap

A 104-week, implementation-driven roadmap with a two-stage career direction: **AI Engineering first → AI Research Engineering next**.

- **Target duration:** 18–24+ months (flexible; not a hiring guarantee)
- **Weekly commitment:** 5–7 hours; plan around 6
- **Primary language:** Python, building on existing software engineering experience
- **Deep learning framework:** PyTorch
- **Working principle:** practical delivery and evaluation from the beginning; mathematical depth grows continuously

## 1. Career direction

### Stage 1 — Senior Software Engineer → AI / Applied AI Engineer
**Indicative horizon: months 1–12.**

Build the ability to design, implement, evaluate, deploy, and maintain AI-enabled products. Focus on LLM applications, RAG, AI backend architecture, quality evaluation, observability, security, latency, and cost.

Target roles to assess include Senior AI Engineer, Applied AI Engineer, AI Product Engineer, AI Platform Engineer, ML Platform Engineer, AI Infrastructure Engineer, and selected AI Forward Deployed Engineer roles.

Begin assessing real vacancies and applying when portfolio evidence matches role requirements. Do not treat a calendar milestone as proof of job readiness.

### Stage 2 — AI Engineer → AI Research Engineer
**Indicative horizon: months 12–24+.**

Deepen classical ML, deep learning, PyTorch, Transformers, model adaptation, paper reproduction, GPU systems, and independent research. The long-term goal is to understand research papers, reproduce results, and develop and test original ideas.

## 3. Phase objectives and deliverables

### Phase 1 — Python and Mathematics Foundations (Weeks 1–4)
Python fundamentals, typing, collections, testing, vectors, matrices, linear combinations, dot product, norms, and basic algorithmic practice.

**Deliverables:** tested Vector implementation, Python exercises, mathematical notes, and Two Sum solutions. Use Python as the primary ML language while relating concepts to familiar C#/.NET engineering patterns.

### Phase 2 — LLM Application Engineering (Weeks 5–8)
LLM APIs and local model basics, prompt construction, structured outputs, tool/function calling, conversation state, error handling, and basic evaluation.

**Deliverable:** a small working LLM application with tests, documented design decisions, and a repeatable evaluation set.

### Phase 3 — RAG and Production AI Engineering (Weeks 9–16)
Document ingestion, parsing, chunking, embeddings, vector search, retrieval quality, reranking concepts, citations, hybrid search, evaluation, prompt-injection risks, privacy, observability, latency, cost, Docker, and service integration.

**Deliverable:** a portfolio-ready RAG service with a reproducible evaluation, failure analysis, tests, operational documentation, and a .NET integration boundary.

### Phase 4 — Classical Machine Learning (Weeks 17–28)
Supervised/unsupervised learning, regression, classification, loss functions, optimization, metrics, regularization, trees, ensembles, KNN, Naive Bayes, clustering, PCA, cross-validation, and error analysis.

**Deliverable:** an end-to-end ML pipeline with a baseline, reproducible experiments, and model comparison.

### Phase 5 — Deep Learning and PyTorch (Weeks 29–44)
Perceptrons, neural networks, backpropagation, autograd, training loops, optimizers, regularization, data loading, CNNs, sequence models, GPU training, and debugging.

**Deliverable:** a tested PyTorch training pipeline and a trained model with recorded configurations and metrics.

### Phase 6 — NLP and Transformers (Weeks 45–56)
Tokenization, language modeling, embeddings, attention, positional information, encoder/decoder architectures, Transformer blocks, generation, and evaluation.

**Deliverable:** a small Transformer implementation and an explanation of tensor shapes and core equations.

### Phase 7 — LLM Adaptation and Fine-tuning (Weeks 57–68)
Pretraining concepts, data preparation, supervised fine-tuning, LoRA/QLoRA, quantization, instruction tuning, preference optimization concepts, and LLM evaluation.

**Deliverable:** a fine-tuning experiment comparing a baseline and adapted model, with quality and resource measurements.

### Phase 8 — Research Paper Reproduction (Weeks 69–84)
Paper selection, critical reading, reproduction planning, architecture reconstruction, baselines, implementation, ablations, result comparison, and research-style reporting.

**Deliverable:** at least one bounded reproduction with code, configurations, results, deviations, and limitations. A small-scale reproduction is acceptable when compute constraints are explicit.

### Phase 9 — ML Systems, GPU and Performance (Weeks 85–96)
CPU/GPU architecture, CUDA concepts, profiling, numerical precision, memory optimization, quantization, inference/KV cache, distributed training, serving, and benchmarking.

**Deliverable:** a model serving or optimization project with measured performance and reproducible methodology.

### Phase 10 — Independent Research and Portfolio (Weeks 97–104)
Topic selection, literature review, hypothesis, baseline, proposed method, controlled experiments, ablations, evaluation, writing, and portfolio review.

**Deliverable:** an independent research report and a coherent public portfolio.

## 5. Weekly time model

Default plan: **6 hours per week** (within the 5–7 hour range).

| Activity | Time |
|---|---:|
| Mathematics and theory | 1.25 h |
| Implementation | 2.75 h |
| Experiments and evaluation | 0.5 h |
| Notes and portfolio | 0.5 h |
| MAANG preparation | 1 h |
| **Total** | **6 h** |

If a week is especially implementation-heavy, shift time between theory and coding while preserving the overall budget. Keep the one-hour interview track sustainable.

## 6. Portfolio projects

1. Production RAG system.
2. Classical ML pipeline.
3. Transformer and fine-tuning project.
4. Research paper reproduction.
5. ML systems optimization / serving project.

Every substantial project should include a clear problem statement, setup instructions, tests, baseline, evaluation metrics, experiment configuration, results, limitations, and a concise technical explanation.

## 7. MAANG preparation track

Maintain approximately one hour per week. Rotate through:
- Algorithms and data structures.
- C# standard library, collections, async/await, and multithreading.
- Practical coding exercises.
- System design.
- Behavioral and senior-level engineering examples.

Prioritize consistent practice over trying to cover every topic each week.

## 8. Adaptation rules

- Re-plan when work or family commitments reduce available time; do not mark unfinished work complete.
- Applied AI work starts early; mathematics continues in parallel and deepens as needed.
- Prefer small, testable models and datasets when local compute is limited.
- Choose project scope based on evidence and available hardware, not ambition alone.
- Revisit prerequisites when experiments expose a knowledge gap.
- Review current job descriptions regularly; adjust the near-term portfolio to match recurring requirements.
